# Practical improvement candidates

These are proposals for later discussion, **not features already implemented**. Prefer them in this order; release them with the pending notification change after deciding scope and testing real workflows.

1. **Missed-alert view after fullscreen or Focus Assist.** Show a persistent in-app count and time range of matching projects that arrived while banners might have been hidden. Use persisted arrival events rather than resending all suppressed OS toasts. Why: prevents a silent missed opportunity without relying on OS overlays. Distinguish app DND (intentional suppression) from OS suppression, which RASED cannot observe reliably.
2. **Local relevance ranking of matching projects.** Add an explainable score from the user's saved categories, keywords, budget and project age; show why each project ranks highly. Why: when several projects arrive together, users can open the best-fit ones first. Keep it on-device, deterministic, and opt-in; existing filters remain authoritative.
3. **Fast manual proposal preparation.** Save a few local proposal templates and copy a selected one with clearly identified placeholders (price, timeline, relevant portfolio). Why: reduces time from spotting a project to preparing a personal application. Never submit automatically; user reviews content on Mostaql.
4. **Arrival-delay diagnostics.** Surface RSS publication time, first successful feed observation, notification submission, failed checks and backoff intervals in a small diagnostics view. Why: shows whether delay comes from Mostaql's feed, network, filtering, or RASED, before changing the scan rate.
5. **Complete user-data backup and restore.** Offer explicit export/import of the local database, including bookmarks, notes and read/submitted states, with validation and a pre-restore backup. Why: reinstalling or switching computers should not lose personal organization. Existing settings-only export does not cover this.

Avoid a fullscreen overlay that steals focus from games: it could minimize a game, still fail with exclusive fullscreen, and would ignore the user's Windows notification preferences. Validate each proposal against actual users and the existing 0.2.6 feature set before committing it to a release.
